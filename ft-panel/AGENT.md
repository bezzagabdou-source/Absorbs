# وكيل تطوير FT

اللوحة مشروع Node/HTML منفصل عن بوت Next.js. يُرسل المساعد تقدّم الأدوات مباشرة، ويضع تعديلات الملف في مسودات Redis مشفّرة. زر «الفرق» يعرضها؛ زر «نشر المسودات» ينشئ التزاماً غير إجباري الدفع على الفرع المهيأ، ثم يبدأ بناء الإنتاج للمشاريع المتغيّرة. ظهور `QUEUED` أو `BUILDING` لا يعني نجاح النشر؛ تحقّق من `READY` و`PROMOTED` والأسماء المستعارة. يتوقف النشر إذا تغيّر رأس الفرع. زر التراجع يعيد آخر مسودة أو تعديل قاعدة بيانات مدعوم أو أوامر تيليغرام؛ للتراجع عن نشر يُنشأ التزام عكسي ويبدأ بناء جديد، ولا يكون الإنتاج قد عاد حتى يكتمل البناء.

## متغيرات Vercel للوحة

كل القيم الحساسة تُضبط في Vercel كـ Sensitive، ولا تُكتب في المستودع أو المحادثة.

- `AGENT_GITHUB_REPOSITORY`: افتراضياً `bezzagabdou-source/Absorbs` أو بيانات مستودع Vercel.
- `AGENT_GITHUB_BRANCH`: الفرع المخصص للوكيل؛ إن لم يُضبط يُستخدم `VERCEL_GIT_COMMIT_REF`. القراءة العامة تعمل بلا اعتماد، أما إنشاء الالتزامات فيتطلب `AGENT_GITHUB_TOKEN` بصلاحيات محدودة لهذا المستودع.
- `AGENT_VERCEL_TOKEN`, `AGENT_VERCEL_TEAM_ID`, `AGENT_VERCEL_BOT_PROJECT_ID`, `AGENT_VERCEL_PANEL_PROJECT_ID`: مطلوبة للنشر أو الاستعلام عن حالته/أحداث البناء؛ رقم الفريق اختياري إذا كان نطاق الحساب الافتراضي صحيحاً.
- `AGENT_BACKUP_KEY`: مفتاح ثابت لتشفير المسودات والنسخ؛ عند غيابه يُستخدم `SESSION_SECRET`. تغيير المفتاح دون ترحيل النسخ يجعلها غير قابلة للقراءة.
- اختياري: `AI_MODELS` (الأقوى أولاً؛ افتراضياً `openai/gpt-oss-120b,openai/gpt-oss-20b`)، `AI_MAX_TOKENS`، `OPENROUTER_MODEL`، `BOT_BASE_URL`.
- يحتفظ المشروع بمتغيراته السابقة `REDIS_URL`, `SESSION_SECRET`, `ADMIN_PASSWORD`, `BOT_PANEL_KEY` وأحد مفاتيح مزودي الذكاء الاصطناعي. Vercel Sandbox يتطلب OIDC المفعّل وصلاحية الخدمة؛ الاختبارات تنفَّذ بعيداً عن قاعدة الإنتاج ومن دون أسرار الإنتاج.

## متغيرات البوت

`PANEL_PUBLIC_KEY` هو مفتاح الربط الموجود؛ `AGENT_DB_BACKUP_KEY` اختياري ومستقل لتشفير نسخ قاعدة البيانات، ويُستخدم `ADMIN_SECRET` عند غيابه. يجب إبقاء المفتاح ثابتاً. `AGENT_WEBHOOK_HOST` اختياري لتثبيت النطاق المسموح للويب هوك. يستخدم `PANEL_MAX_OUTPUT_TOKENS` و`PANEL_GEMINI_MODEL` و`PANEL_OPENROUTER_MODEL` فقط لمسار النموذج الاحتياطي.

## الحدود المهمة

- `db_query` و`db_update` هما قراءة/تحديث مفاتيح JSON على Postgres، وليسا SQL حراً. التحديث ذرّي ويتطلب الإصدار المقروء ويخزّن نسخة مشفّرة في نفس المعاملة. النقاط والإعدادات والطلبات تستخدم الأدوات المتخصصة للمحافظة على العلاقات. التخزين غير Postgres لا يدعم هذه الأداة العامة.
- عمليات الإدارة والصور القديمة والرسائل/البث لا تملك تراجعاً عاماً؛ الرسائل المرسلة لا يمكن سحبها. تيليغرام لا يعرض سر الويب هوك السابق، لذا قد يلزم استرداده يدوياً. أحداث البناء المتاحة عبر `get_logs` ليست سجلات تشغيل تاريخية.
- البث الحالي مقصور على آخر 50 عضواً كحد أقصى، ويعرض عدد النجاح والفشل الفعلي. المسودات والنسخ تعتمد على استمرارية Redis، ونسخ البيانات على Postgres.
- لا تُشغَّل الاختبارات ولا يُنشر كود عند رفع المسودة وحده. نتائج Sandbox وهمية بالنسبة للخدمات الخارجية؛ توافر المزودين وGitHub وVercel يتطلب اختباراً مصادقاً عليه في بيئتك.

## فحص سريع

1. سجّل دخول المدير، اطلب «اعمل اداعة» بنص واضح وتحقق من النطاق قبل الإرسال.
2. أرفق صورة من الجهاز في المحادثة وفي نموذج جائزة أو مسابقة، واحفظ ثم أعد فتح العنصر.
3. بعد تهيئة التكامل، اطلب قراءة ملف، تعديل سطر، عرض الفرق، تنفيذ الاختبارات، ثم تراجع. انشر فقط عندما ترغب في بدء بناء الإنتاج وراجع حالته.
4. محلياً: `cd ft-panel && npm ci && npm test && npm run check`، و`cd ft-contest-bot && npm ci && npm test && npm run typecheck && npm run build`.
