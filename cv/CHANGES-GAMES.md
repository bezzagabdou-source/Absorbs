# Nexus — إصلاح مصنع الألعاب (v21)

## السبب الجذري لضعف/فشل الألعاب وبطئها
- كل لعبة كانت تُدفع إلى **3 ميغابايت و6000+ سطر** عبر حتى **120 جولة استمرار** (titan) → بطء شديد، تكرار كود، أخطاء، ملفات مبتورة.
- عقد GAME_MASTER القديم كان يمنع الإنترنت تمامًا ويفرض حجمًا تجاريًا ضخمًا.
- أي طلب فيه "ضخمة/كبيرة/احترافية" كان يدخل **Game Forge**: مشروع 3D متعدد الملفات (15+ ملف) بدل لعبة موبايل تعمل.
- المستخدم المجاني لم يكن يحصل على أي عقد جودة للألعاب.
- طلب قصير مثل "لعبة ثعبان" لم يُعتبر طلب بناء.

## ما تغيّر
- `src/lib/mobile-game.ts` (جديد): عقد **لعبة موبايل** (يتبع طلب المستخدم حرفيًا، لمس/أصابع، 100dvh، 800–2500 سطر، boot آمن، حلقة لا تموت) + `window.NexusNet`.
- **إنترنت للألعاب**: `NexusNet.image/sound/json/text/font/script` — تحميل مباشر ثم بروكسي احتياطي؛ لا تُلقي أخطاء ولا تعلّق (مهلة)، وتسقط إلى الرسم بالكود.
- `src/app/api/asset/route.ts` (جديد): بروكسي تنزيل آمن (https، حظر العناوين الخاصة SSRF، 8MB، مهلة 9ث، أنواع ملفات محددة، تحديد معدل).
- CSP في المعاينة (`game-preview`, `artifacts-panel`, `workbench`) يسمح الآن بـ https للصور/الصوت/الخطوط/connect، مع Google Fonts.
- **السرعة**: ألعاب = هدف 28KB وحد أقصى 3 جولات (كان 3MB/120)، محرك واحد سريع بدل دمج عدة مسودات، لا epic، لا Academy، mode=speed.
- Forge متعدد الملفات صار اختياريًا فقط (يُطلب صراحة "multi-file / مشروع متعدد الملفات").
- كشف النية: "لعبة ثعبان"، "العاب سيارات" = بناء؛ "كيف أصنع لعبة؟" = جواب نصي (إصلاح مشكلة حدود الكلمة في العربية).
- أداة game-builder تستعمل نفس العقد (أزيل "5000+ سطر" و"لا شبكة").
- المستخدم المجاني يحصل الآن على عقد اللعبة أيضًا.

## تحديث: ألعاب 3D وضخمة (بدون كسر)
- مستوى جديد BIG لطلبات 3D / ضخمة / كبيرة / RPG / FPS / سباق / عالم مفتوح: ملف واحد 2500–6000 سطر، ميزانية 90KB و5 جولات كحد أقصى (بدل 3MB/120).
- Three.js r128 فقط من cdnjs كوسم عادي؛ قائمة محظورات لواجهات غير موجودة في r128 (CapsuleGeometry, Geometry, colorSpace, OrbitControls…).
- الفاحص `html-verify` صار يكتشف: THREE بدون تحميل، نسخة/وحدة ES خاطئة، واجهات r128 غير الموجودة، ثم الإصلاح التلقائي يصلحها بتعديلات صغيرة.
- شاشة تحميل + فحص WebGL مع بطاقة خطأ بدل الشاشة السوداء؛ جودة تنخفض تلقائيًا على الهاتف؛ لا يعتمد على pointer lock.

## توزيع المهام بين النماذج (بناء الألعاب)
- **الكاتب** (مهمة `build`): Claude ← Hugging Face ← Gemini ← DeepSeek ← Grok ← OpenRouter. (Cerebras وGroq آخرًا لأن مخرجاتهما محدودة بـ8k توكن.)
- **المصلّح** (مهمة `repair`): المحاولة الأولى Cerebras ثم Groq (سريع)، والثانية تصعيد لأقوى محرك متاح. الإصلاح يُقبل فقط إن قلّل الأخطاء.
- كل محرك له مفتاح يدخل تلقائيًا؛ ما لا مفتاح له يُتخطى، وإن سقط أحدهم يكمل التالي.
## الإنترنت للـAI
- يفتح الروابط ويحمّل الملفات (zip/json/csv/صور/pdf) ويفحص المواقع، ويبحث تلقائيًا عند طلبات مثل "حمل/من النت/افحص موقع/ابحث".
- **فحص روابط CDN**: أي `<script src>` أو stylesheet أو `NexusNet.script` تُفحص فعليًا (GET)؛ الرابط الميت = خطأ يُصلح تلقائيًا قبل وصول اللعبة للمستخدم.

## v12 — لعبة بلا أخطاء: فحص تشغيل حقيقي + قاعدة أخطاء
- `src/lib/game-smoke.ts` (جديد): بعد توليد اللعبة تُشغَّل فعلياً على الخادم داخل vm معزول (بدون شبكة/ملفات، مهلة صارمة) مقابل متصفح وهمي: يكشف ReferenceError، "before initialization"، الأزرار الميتة (handler يرمي خطأ)، انهيار أول إطارات الحلقة، والحلقات اللانهائية. اختُبر على ألعاب سليمة بلا إنذارات كاذبة.
- `html-verify.ts` يستدعيه تلقائياً؛ أي خطأ صلب يدخل نفس مسار الإصلاح الجراحي الموجود (حتى 3 جولات).
- `src/lib/game-kb.ts` (جديد): قاعدة قواعد الأخطاء الشائعة (زر البداية، ترتيب التعريف، الصوت، اللمس، Three r128...) تُحقن في أمر التوليد (وقاية) وفي أمر الإصلاح حسب الخطأ الفعلي (علاج). أضف سطراً جديداً هناك لكل نمط خطأ جديد.
- المعاينة: `crossorigin` تلقائي للسكربتات الخارجية + اسم الملف/السطر في الأخطاء بدل "Script error."
